# Required Try-It Activity 22.1: Reading Big Data

After comparing the Apache Parquet and Apache Feather formats on a large dataset, I found that Feather generally performed better for both reading and writing operations. Feather is optimized for fast input/output and uses a lightweight binary format based on Apache Arrow, allowing data to be written and loaded with minimal overhead. This makes Feather particularly useful for short-term storage, experimentation, and rapid data exchange between applications.

Parquet also performed well, but its write operations were typically slower because it applies additional encoding and compression techniques. While this introduces some overhead during file creation, Parquet often produces smaller file sizes and provides significant advantages for long-term storage and analytical workloads.

The primary difference between the two formats is their design goals. Feather prioritizes speed and low memory usage, whereas Parquet prioritizes compression efficiency, storage optimization, and compatibility with large-scale analytics platforms such as Apache Spark, AWS Athena, Databricks, and DASK. Because Parquet compresses and organizes data for analytics, it may be slightly slower during read and write operations but often provides better performance for large-scale querying and storage.

A publicly available dataset that would benefit from Parquet storage is the NYC Taxi Trip Records dataset, which contains millions of taxi ride records and exceeds 500,000 rows. The dataset includes pickup and drop-off locations, timestamps, trip distances, fares, and passenger counts. Because this dataset is frequently used for analytics and machine learning projects, storing it in Parquet format would reduce storage requirements, improve query performance, and integrate well with big data tools such as Spark, DASK, and cloud-based analytics platforms. For large historical datasets that are queried repeatedly, Parquet is generally the more practical choice.
